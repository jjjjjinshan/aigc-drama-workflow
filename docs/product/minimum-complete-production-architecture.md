# 最小完整生产闭环：架构决策提案

状态：基于[产品闭环基线](production-workflow-portfolio-plan.md)和[现状审计](current-capability-audit.md)的实现设计提案。

## 1. 设计决策

### D1. 创作真相与剪辑真相分开，各自只有一个 Owner

保留创作者可读 Markdown 作为故事、角色、镜头和媒体提示词的权威。增加一个可选但成片输出前必须接受的 `成片编排.md` 阶段产物，由成片编排阶段拥有：

- 已接受的镜头/片段顺序、剪入剪出点和转场；
- 对白/TTS 资产与角色、台词行的绑定；
- 字幕来源与呈现方式、经审阅的字幕时间；
- 音乐/音效在整集中的落点、淡入淡出、ducking 意图；
- 经创作者确认的输出配置。

它只记录剪辑与合成决定，不重写剧情、对白、镜头运动提示词或音乐创作意图。若改编内容或表演规格有误，应回到对应 owner 修复。成片编排由结构化检查器编译为内部 JSON 时间线；编译结果不能成为第二份人工维护的真相。

### D2. 依赖调度只能编排任务，不能绕过逐项成本确认

镜头 DAG 负责识别可并行任务和 `CHAIN_PREV` 依赖。每个可能产生外部费用的媒体 job 继续单独走 `prepare → creator confirm → run`。调度器可以停在待确认集合并展示数量、依赖和费用预览；不得以一次集合确认替代每个 job 自己的精确确认。失败或等待中的父任务不得启动子任务。

对 `CHAIN_PREV`，父视频尾帧作为生产运行时生成的输入快照，而不是用户随手加到 job JSON 的字段：

1. 校验父 job 已成功，父片输出仍与成功运行记录的大小/校验和一致；
2. 在 prepare 时抽取尾帧，并将帧路径、帧字节摘要、父 job ID 和抽帧规则纳入子任务指纹；
3. 向 Adapter 传递有明确 `role` 的尾帧输入，同时保留 creator-authored `reference_bindings` 的精确匹配规则；
4. confirm 显示该输入及其控制边界；任何父片或抽帧策略变化使旧确认失效；
5. 记录子输出所依据的父输出版本，审计可反向追溯。

因此 `head_frame` 不能只在 DAG 层临时注入；它必须进入 production runtime 的规范化、指纹、确认和 Adapter 契约。

### D3. 时间线用受限 EDL 编译为 FFmpeg 命令

采用本地 FFmpeg 做确定性剪切、拼接、静态字幕渲染/外挂字幕、音频混合和封装；不把模型用于剪辑时间算术，也不接受任意 shell 字符串。运行器从已审阅的 `成片编排.md` 生成受限的内部 EDL，并用 argv 调用 FFmpeg。

首版支持：

- 有序视频片段及明确的 in/out；
- VO/TTS、配乐和音效的时间偏移、音量、淡入淡出；
- 从权威台词投影并经审阅的 SRT；烧录字幕或外挂 SRT（二选一由项目配置决定）；
- 画幅、分辨率、帧率、音频/视频编码与封装配置；
- 输出到新的 run/version 目录，不静默覆盖已交付成片。

首版不做复杂图形特效、自动口型、转场模板库、多轨非线性编辑器或任意插件系统。需要精细审美处理时，允许剪辑师在专业软件中手工精修，并把最终版本、采用的素材清单和人工变更记录作为交付观察；不能宣称这些步骤由系统自动完成。

### D4. 最终成片包独立于文本/JSON 交付包

保留 `project_tool` 的批准文本/JSON 包装与校验机制，不将视频硬塞进只接受 UTF-8 的接口。新增媒体成片 manifest，记录：

- 成片、字幕、音轨及关键中间素材的相对路径、媒体类型、大小和 SHA-256；
- timeline/EDL 版本及源 Markdown/job/output 的摘要；
- 实际渲染配置、工具版本、生成时间、运行状态；
- 技术检查结果与人工审片观察的引用；
- 明确排除的输入和原因。

私有试产的成片、小说、衍生文本、密钥和运行环境信息留在本机工作区。公开仓库只提交代码、合成样例、脱敏验证结果，以及用户单独批准公开的原创素材。

### D5. TTS 保持 Provider 可替换，但先做一个可验证的实际路径

production runtime 已声明 `tts` modality，但没有内置 TTS Provider。设计一个 utterance 级 Adapter 输入：准确台词、角色/声线绑定、语言/发音说明、表演状态、参考输入、输出音频。实现第一条 TTS 路径前核实用户可访问的服务、许可、读音修正、声音一致性、价格和留存政策；不预选供应商，也不把音色克隆作为默认需求。若实际试产决定人工录音/导入优于 TTS，工作流也必须能将人工录音作为有来源的媒体资产进入同一时间线。

## 2. 端到端运行关系

```text
创作 Markdown
  → 结构与内容审查
  → 媒体 job 预览 / 用户确认 / Adapter 生成
  → 依赖完成与素材核验
  → 成片编排 Markdown（剪辑唯一权威）
  → 受限 EDL + SRT 编译
  → FFmpeg 本地组装到新版本目录
  → 技术检查 + 人工审片 / 定点返工
  → 带来源和校验信息的私有成片包
```

生成、组装、审片是不同状态：`media_generation_succeeded` 只表示任务输出已落盘；`assembly_succeeded` 表示本地渲染和技术检查完成；只有有证据的审片接受后才能记作 `creator_accepted`。没有观察的维度保持 `unverified`。

## 3. 必须守住的不变式

1. **不花钱不绕闸**：任何外部媒体生成只在精确输入和参数被确认后启动；本地 FFmpeg 组装不收费，但也不能静默覆盖用户版本。
2. **输入封闭**：项目相对路径、允许扩展名、大小/时长上限、普通文件和无符号链接检查；Adapter 使用 argv，不执行来自 EDL 的 shell 文本。
3. **来源可追溯**：每个时间线 clip/音频/字幕段绑定当前接受的来源版本；来源变更必须重编译、重新预览并重做受影响审查。
4. **最小返工范围**：镜头输出改变只使依赖该输出的尾帧链、成片时间线和交付证据失效，不重做不相关素材。
5. **技术结论不越界**：媒体探测可以检查可解码、时长、画幅、帧率、音轨、字幕和响度等技术事实；人物身份、表演、连贯性、口型和审美仍需人看/听并记录。
6. **失败可恢复**：每次渲染使用临时目录，只有完整校验成功才原子发布新版本；崩溃或 FFmpeg 错误不得留下伪成功成片或破坏上个版本。

## 4. 实施次序与验收

| PR | 范围 | 最小证明 |
|---|---|---|
| P0a | PR #1 经用户审阅合并后，统一生产 job 输入契约；修复 `CHAIN_PREV` 进入 fingerprint、confirmation 和 Adapter 的路径 | 纯离线：父任务成功、缺帧、父输出被改、确认过期、子任务 Adapter 输入均有针对性用例 |
| P0b | DAG 从“仅打印依赖图”转为可停靠调度，生成待确认 job 列表并按父子关系调度；继续复用 prepare/confirm/run | fixture adapter：根任务并行、子任务等待、失败不向下游传播、重试需要新确认 |
| P0c | 成片编排 Markdown 契约、解析/校验器、SRT 投影和受限 EDL 编译 | 合成素材：时长/引用错误 fail-closed；编译稳定；不执行 EDL shell 内容 |
| P0d | FFmpeg 组装、临时输出、媒体探测、版本化 manifest 与交付校验 | 自动生成合成短片，验证片段顺序、音轨/字幕存在、时长/编码正确、失败不覆盖前版 |
| P1 | 选定并接入一条 TTS 或人工录音导入路径，打通逐字台词、角色声音身份、字幕与混音 | 一段对白跨镜头可听可读，读音/时间可检查，替换单句后局部重建 |
| P2 | 使用用户故事素材私下制作连续三集，选真实缺陷完成完整返工闭环 | 第三节试产验收逐条通过；记录真实时间、费用、失败与创作者审片结论 |

在自动化验收通过后才调用真实媒体服务。每个收费任务先展示当次准确任务和预算并由创作者明确确认。技术实现需用户最终审核 PR；任何合并都留给用户决定。
