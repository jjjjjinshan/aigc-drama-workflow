## 架构结论与优先级

### P0：先打通真实可执行路径

1. PR #1 先由仓库所有者审核；合并后主分支才恢复生产运行时和随附 Provider 入口。
2. 把分镜依赖图接到实际媒体 job 的 prepare → creator confirm → run 生命周期；保留并发限制、失败停机、恢复和每个付费任务的独立授权。
3. 解决 `CHAIN_PREV` 输入的单一权威：父片尾帧必须进入子任务输入快照、确认指纹、Adapter 参考和运行记录；当前字段白名单不接纳该输入，不能在外层临时注入后绕过确认。
4. 定义一个可审查时间线，将生成片段、对白/配音、字幕、音乐/音效映射到时间区间，能确定性组装、导出并记录每个输出使用的源版本。

### P1：用试产决定是否产品化

- 选择一个最适合当前账户、成本和素材边界的 TTS 路径；先验证授权、声音一致性、读音修正、分句与重做成本，再决定内置 Adapter 或人工导入。
- 加入成片级技术检查和有证据的人工审片记录；技术检查不替代审美验收。
- 把交付包边界扩展到成片和相关资产，同时维持输入/凭据排除、路径校验、版本与校验和。

## 目前不成立的产品承诺

- 不能称为从剧本到成片的自动化闭环；当前能证明的是大量创作/校验规范、部分生产控制和部分媒体 Provider 实现。
- 不能声称跨镜头续接、TTS、字幕与时间线剪辑已经跑通。
- 不能把离线自检、文件哈希或 Provider 成功返回作为媒体质量证据。
- 不能报告实际成本、单集工时、首次可用率或提效比例；尚未发生真实试产。
