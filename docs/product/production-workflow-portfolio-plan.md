# AI 漫剧生产工作流：产品闭环与项目验收基线

> 状态：提案，供产品范围与验收评审。这里定义目标与验证办法，不代表相关能力已经实现或通过验证。

## 1. 产品目标

把创作者提供的故事材料转为可观看、可审查、可返工、可追溯的连续漫剧成片。系统服务个人创作者或微型工作室，负责组织创作与媒体生产；创作者保留故事、审美、费用确认和最终交付的决定权。

作品集要证明的是一条真实跑过的生产闭环及其取舍，不是 Skill 数量、架构图或“全自动”口号。核心待验证问题：

1. 从长篇材料到分集剧本，能否保住故事因果、人物动机和跨集连续性？
2. 从剧本到镜头和媒体任务，能否追溯来源、控制状态漂移，并在失败后局部返工？
3. 生成素材能否经配音、字幕、声音、剪辑/合成形成可播放成片？
4. 创作者能否看懂成本和风险、控制外部副作用，并判断质量是否达到可交付标准？

## 2. 端到端产品流程

| 阶段 | 系统/模型职责 | 创作者职责 | 必须留存的证据 / 出口条件 |
|---|---|---|---|
| 需求与项目设定 | 建立创作简报、目标受众、形式候选、约束清单 | 决定作品方向、受众、画幅/平台等重大体验选择 | 已确认的简报与仍待确认项 |
| 原始材料理解与改编 | 分析材料、提出原创化改编方案、分集地图 | 选择改编方向并审定剧情边界 | 来源到改编决策的可追溯记录；不把分析结论冒充作者授权 |
| 分集剧本与资产 | 生成/修订剧本、角色/场景/道具设定 | 审核人物、冲突、集尾与视觉锚点 | 当前版本的创作文档、稳定 ID、覆盖检查 |
| 分镜与媒体规格 | 镜头设计、关键帧与声音/运动/交付规格 | 审查叙事信息、表演、节奏和生成可行性 | 镜头可追溯到剧本；依赖关系有效；冲突和缺失项被发现 |
| 预览、确认、生成 | 计算任务输入与费用预览，调用所选外部工具，记录结果 | 选择工具/参数并确认付费任务 | 确认绑定确切输入；运行状态、产物校验和失败原因可查 |
| 后期组装 | 按时间线组织片段、对白/TTS、字幕、音乐/SFX及转场，导出母版 | 审核剪辑节奏、混音、字幕和成片 | 可播放成片、字幕/音轨/画幅/帧率等交付检查、素材来源与版本清单 |
| 质量审查与返工 | 执行结构检查、语义审查辅助、成片技术检查；定位返工影响范围 | 作出审美裁决并接受/要求返工 | 问题有证据、有责任阶段、有复验结果；旧版与替代版关系清楚 |
| 发布准备 | 打包脱敏的项目说明、验证结果和授权素材 | 审批公开内容及 GitHub 更新 | 自动化检查通过、PR 经用户审核；私有小说与试产素材不进入公开包 |

各阶段可按实际素材跳过不需要的中间步骤，但不得伪造阶段产物。外部生成必须先预览并由创作者明确确认。技术执行成功与内容质量通过是两个独立判断。

## 3. 试产范围与验收

### 范围

- 使用用户本地提供的故事材料，私下连续制作 3 集，验证跨集连续性和返工链路。
- 每集从选定剧本范围开始，跑到带声音、字幕并可播放的完整成片；记录人工介入点、等待、失败、重试和实际费用。
- 画幅、单集时长、视觉风格、平台/模型及剪辑工具暂不冻结；在首个试产任务简报中根据目标体验、可用工具和预算共同确定。
- 小说全文、改编稿、未公开素材与凭据只留在本地私有工作区，不提交公开仓库。

### 通过条件

1. **故事完整**：创作者逐集确认核心冲突、关键选择、因果结果和集尾信息；跨集人物/物件/时间状态无未解释冲突。
2. **镜头可追溯**：随机抽查每集关键镜头，能从成片/时间线定位到媒体素材、镜头规格及剧本依据；改编删并内容有记录。
3. **成片完整**：3 集均能在约定播放设备/播放器中打开；画面、对白、字幕、音乐/音效按已确认规格存在，时长和编码满足所选交付配置。
4. **返工闭环**：至少选取一个真实缺陷，记录发现、责任环节、局部重做、重新组装和复验；不因局部修改静默覆盖未确认素材。
5. **人机边界清楚**：所有产生外部费用的任务均有确认记录；人工审美决定和自动检查结论分开记录。
6. **成本与效率可解释**：逐集记录实际花费、生成等待、人工处理时间、失败/返工次数和成片时长。先建立真实基线，再决定优化目标；本轮不预设虚假的节省百分比。
7. **可复现与可交接**：从脱敏项目包能理解目录、版本、所用工具及已知限制；私有输入可被排除，公开材料经过用户确认。

任何“质量通过”都需有创作者或审查者的内容判断证据；文件存在、哈希一致或供应商返回成功只能证明执行/保管状态。

## 4. 对当前仓库的产品审视

仓库已具备多阶段创作 Skills、创作者可读文档约定、阶段契约、离线检查器、媒体任务确认/审计机制、Adapter 契约，以及面向内容问题的质量审查规则。这些构成了不错的生产控制面。

目前不能仅凭这些规范宣称已经具备完整成片产品。接下来的架构审查和试产要实证以下链路：

- 调度器是否能从依赖图真正驱动任务执行，并把父镜尾帧等依赖传给子任务；
- 当前配置下图像、视频、TTS、音乐等能力分别由什么工具执行、输入输出如何校验，缺少的 Provider 是否由本地工具或人工步骤承担；
- 多镜头、多音轨、字幕、片头/片尾及成片交付规格如何汇总为时间线并导出；
- 组装结果如何回链到镜头和来源，局部替换素材后怎样安全重建与复验；
- 工作流在真实创作者使用时是否可理解，费用、等待、失败和恢复情况是否可见。

这些是待核验的问题，不应预先假定每项都要新造一个模块。优先复用已存在的工具与契约，只有端到端试产证明有缺口时才扩展实现。

## 5. 项目阶段、交付物与决策门

| 阶段 | 工作 | 可审查交付物 | 进入下一阶段的门槛 |
|---|---|---|---|
| A. 产品基线 | 确认用户、场景、流程、试产范围、质量口径及隐私边界 | 本文；试产任务简报模板 | 用户审阅产品边界与试产验收 |
| B. 现状与架构核验 | 运行现有自检；沿一个代表任务追踪输入、依赖、外部任务、音视频、导出和审查 | 能力/缺口矩阵；一条实际执行证据链 | 每项结论标注“已实现且验证 / 仅有规范 / 不存在 / 未知”；确定最小可行设计 |
| C. 工作流设计 | 定义最小端到端交互、资产/任务关系、时间线交付、异常恢复和人工门 | 架构决策记录、流程图、验收用例 | 方案能覆盖试产失败与局部返工，且不泄露私有素材 |
| D. 分段实现 | 按生产链路分 PR：先补最短成片路径，再补经试产证明必要的能力 | 小而可审查的 PR、针对性自动化检查 | 各 PR 的直接检查通过；不提前接入未选定或未批准的付费服务 |
| E. 离线与集成验证 | 用合成 fixtures 验证调度、失败恢复、时间线组装、导出及脱敏边界 | 检查结果、样例包、问题清单 | 关键失败路径可预测，产物契约清楚 |
| F. 私下三集试产 | 用用户素材、选定工具和已确认预算实际制作三集 | 本地产物、逐集观测记录、费用与返工数据 | 达到第 3 节验收；未达项有决策：修复、降级或缩小承诺 |
| G. 整改与发布候选 | 修复阻断问题，重跑受影响验证，整理脱敏作品集说明 | 发布候选版本、验证摘要、公开素材清单 | 用户审核所有公开内容及 GitHub PR |
| H. GitHub 更新 | 将用户批准的代码和文档经 PR 合并到远程主仓库 | 已审 PR / 合并提交 | 只在用户审批后合并；此项目的“上线”指 GitHub 仓库更新，不默认代表托管服务上线 |

各阶段可并行写作和审查，但阶段证据不能互相替代。任何范围、成本、素材公开或产品承诺的重大变化都回到对应决策门记录。

## 6. 关键指标

试产先记录基线，不预设缺乏依据的提升承诺：

- 端到端完成率：进入生产的镜头/音频任务中，最终进入成片的比例及排除原因；
- 返工率与返工半径：多少产物需要重做，一次局部修改牵动多少上游/下游工件；
- 首次可用率：第一次生成即可进入审片的比例，按模态区分；
- 单集成本：模型/平台费用、重试费用，分别列出；
- 单集人工时长与等待时间：创作者操作/审片时间和外部生成等待分开计；
- 内容质量：故事覆盖、连续性、音画/字幕问题及创作者是否接受，附具体证据；
- 可追溯性：抽查成片片段能否定位到当前任务输入、版本和来源。

## 7. 不纳入首轮承诺

- 无人审核的一键批量制作和自动发布；
- 对所有模型、所有剪辑软件的通用兼容；
- 声称客观保证“电影级质量”、固定 ROI 或固定生产提效百分比；
- 公开未经用户批准的小说、改编文本、原始素材或成片；
- 在真实任务证明价值前，为每种模态单独建设复杂平台或服务。
