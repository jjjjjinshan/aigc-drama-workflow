# 架构说明

本文说明工作流的整体结构：有哪些层、每层负责什么、产物如何在层之间流动。

## 设计目标

让**长篇小说改编成连续剧**这件事具备工程属性——可复现、可追溯、可交付。

具体拆解为三个可验证的目标：

1. **状态可证明** —— 任何跨镜头、跨场、跨集的状态变化，都能追溯到一份显式记录，而不是「模型记得」。
2. **边界可执行** —— 每个环节只写自己的产物，越权写入在结构上就不被允许。
3. **质量可定位** —— 问题必须落到具体文件、具体镜头、具体行，并指明由哪个 owner 修复。

## 五层流水线

```
┌─────────────────────────────────────────────────────────┐
│ 输入层    长篇小说 / 连载网文 / 故事想法                  │
├─────────────────────────────────────────────────────────┤
│ 开发层    原著分析  ──▶  开发立契                         │
│           （拆解）      （立约）                          │
├─────────────────────────────────────────────────────────┤
│ 创作层    剧本 → 视觉设定 → 图片提示词                    │
│                 → 分镜   → 视频提示词                     │
├─────────────────────────────────────────────────────────┤
│ 生产层    生产执行  /  Flow 生产包                        │
├─────────────────────────────────────────────────────────┤
│ 产出层    成片 · 交付包                                   │
└─────────────────────────────────────────────────────────┘
```

### 输入层

不可变的创作者输入。原著文件放 `输入/`，本阶段只读。

### 开发层

**原著分析**：把长材料变成能被引用、能被反驳、能被接着用的分析层。目标不是复述剧情，而是找出每一段承担的戏剧功能，并说明它在竖屏短剧里值多少钱。

管道为 6 阶段：索引 → 快评 → 逐章提取 → 单元聚合 → 人物归并 → 改编价值。其中索引是**唯一切片真源**——如果每个阶段各跑一次正则，就会切出互相对不上的章节，而且没有人会发现。

**开发立契**：把创作者意图变成能持续制造选择、代价与状态变化的故事系统。区分不可改的事实、可探索的空白与形式约束，产出创作简报、故事引擎与分集地图。

每集必须记录进入状态、当集追求、阻力、方向性转折、当集结果、信息释放、出去的压力，以及下一集必须继承的事实。

### 创作层

单集创作的核心是**五份 creator-first 文档**：

| 文档 | owner | 内容 |
|---|---|---|
| `剧本.md` | write | 场景、动作、对白、生产标签 |
| `视觉设定.md` | assets | 人物、造型、地点、道具、状态变化 |
| `图片提示词.md` | image-prompts | `IMG-*` 资产板提示词 |
| `分镜.md` | storyboard | `SHOT-*` 镜头与冻结关键帧 |
| `视频提示词.md` | video-prompts | `MOTION-*` 运动与音乐 |

依赖关系上，`剧本` 是主线，`视觉设定 → 图片提示词` 与 `分镜 → 视频提示词` 是两条并行支线。但图片提示词与分镜是**兄弟分支，不互相等待**——已有视觉事实就能写分镜，已有剧本就能拆资产。

### 生产层

**生产执行**：在创作者明确确认后，把已写好的生产规格送到运行环境配置的 adapter。四步硬闸门，顺序不可合并：

```
job → prepare → confirm → run
```

`prepare` 只验证并预览，不生产；`confirm` 只保存与当前 job 指纹绑定的一次性确认；`run` 才启动 adapter。job、prompt、参数、输出路径任一变化，旧确认立即失效。

**Flow 生产包**：把已确认的剧本、视觉设定、分镜与关键帧，转换成可检查、可逐镜执行、可回审的 Google Flow 交接包。连续性来自显式状态，不依赖模型记忆。

### 产出层

成片与交付包。归档只复制用户点名的当前文档和成品，排除私有输入、凭据、绝对路径与隐藏运行状态。

## 两个横切能力

### 路由与项目配置（`short-drama`）

贯穿全流程：项目初始化、跨阶段路由、本地 Dashboard、制作形态与视觉方向决策。

它不创作任何阶段正文，只负责把请求交给正确的 owner，并管理项目级配置。

### 审查（`short-drama-review`）

可在任意阶段介入。**优先由未参与当前版本创作的 reviewer 执行**；条件不允许时可以自检并如实说明。

审查与修改是两个独立工作单元：审查只定位问题、影响和必须达到的修订结果，不在同一轮替 owner 改来源。

支持 10 种审查范围：`source_analysis`、`story_script`、`assets_continuity`、`image_prompts`、`storyboard_keyframes`、`video_prompts`、`production_outputs`、`full_episode`、`delivery_privacy`、`project_calibration`。

## 文档产出链

```
输入/原著.txt
   │
   ├─▶ 项目开发/source-analysis/     ← 分析层（索引、提取、聚合、候选）
   │
   ├─▶ 项目开发/                      ← 开发层（简报、引擎、分集地图）
   │
   ├─▶ episodes/<EP>/                 ← 创作层（五份文档）
   │      ├── 剧本.md
   │      ├── 视觉设定.md
   │      ├── 图片提示词.md
   │      ├── 分镜.md
   │      └── 视频提示词.md
   │
   ├─▶ assets/lookdev/                ← 本地 Lookdev 资产库（定妆照 / 概念图 / 道具卡）
   │
   ├─▶ dist/<EP>/                     ← 生产层（图片、视频、音频）
   │
   ├─▶ flow/<EP>/                     ← Flow 生产包
   │      ├── flow-package.json
   │      ├── continuity-ledger.json
   │      ├── shot-cards/
   │      └── review/
   │
   └─▶ 审查/<EP>-审查.md              ← 质量层
```

> 旧的 `剧集/<EP>/` 与 `剧集|episodes/<EP>/制作成果/` 仍然可读，但新项目一律用 `episodes/<EP>/` 与 `dist/<EP>/`。

## 所有权矩阵

每个产物有且只有一个 owner。下游只读上游，发现问题写审查报告并路由回正确的层。

| 产物 | owner |
|---|---|
| `项目开发/source-analysis/**` | `short-drama-novel-analyze` |
| `项目开发/creative-brief.md` 等 | `short-drama-develop` |
| `episodes/<EP>/剧本.md` | `short-drama-write` |
| `episodes/<EP>/视觉设定.md` | `short-drama-assets` |
| `episodes/<EP>/图片提示词.md` | `short-drama-image-prompts` |
| `episodes/<EP>/分镜.md` | `short-drama-storyboard` |
| `episodes/<EP>/视频提示词.md` | `short-drama-video-prompts` |
| `dist/<EP>/**` | `short-drama-produce` |
| `flow/<EP>/**` | `google-flow-manga` |
| `审查/**` | `short-drama-review` |
