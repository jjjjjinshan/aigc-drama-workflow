# assets/lookdev/ —— 本地 Lookdev 资产库

资产定妆照、场景概念图与道具卡的存放位置。它是创作链路里唯一一处"已渲染资产"的落点：
分镜从这里取参考帧，图生视频从这里取首帧。

## 三步管线

1. **资产定妆**：`short-drama-assets` 从剧本抽出唯一资产 ID（`CHAR_001`、`SCENE_001`、`PROP_001`），
   `short-drama-image-prompts` 把它们写成 `episodes/<EP>/图片提示词.md` 里的 `IMG_...` 条目。
2. **资产库锁定**：条目渲染完成后存进本目录。文件名用 `<资产ID>_<用途>.png`：

   ```text
   assets/lookdev/
   ├── CHAR_001_定妆照.png
   ├── SCENE_001_概念图.png
   └── PROP_001_道具卡.png
   ```

   渲染走 `short-drama-produce` 的四步硬闸门，落盘目标写 `dist/<EP>/lookdev/...`，
   确认后再复制进本目录。`IMG_...` 条目本身不代表图片已生成。

3. **动态渲染**：`short-drama-storyboard` 在分镜的「输入参考图」里按完整 `REF-...` 语法引用本目录的
   图片；`short-drama-video-prompts` 写运动提示词；adapter 把首帧图（Base64 或云端临时 URL）
   与运动提示词一起提交给图生视频模型。

## 命名约定

| 段 | 取值 |
|---|---|
| 资产 ID | 与 `视觉设定.md` 一致：`CHAR_001` / `SCENE_001` / `PROP_001` |
| 用途 | `定妆照` / `概念图` / `道具卡` / `变体` 等中文短词 |
| 扩展名 | `.png`（需要透明通道时用 `.webp`） |

同一资产有多个状态变体时，在用途后追加状态词，例如 `CHAR_001_定妆照_湿身.png`。

## 版本控制

图片是二进制且体积大，本目录下的 `*.png`、`*.jpg`、`*.webp`、`*.psd` 已被 `.gitignore` 忽略。
仓库只保留本说明文件。需要给资产做版本时，把定妆用的提示词留在 `图片提示词.md` 里——
提示词可 diff、可回滚，图片不用入库。

## 与 输入/ 的分工

- `assets/lookdev/`：**本项目生成**的资产图，可随提示词变更重新渲染。
- `输入/`：**创作者提供**的素材，不可变，是分析层的来源。

两者都以项目相对路径写进生产 job 的 `reference_bindings`。
