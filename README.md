# AIGC 漫剧 / 短剧创作 Agent 工作流 (aigc-drama-workflow)

> 面向个人创作者与 3 人以下微型工作室的多 Agent 编排系统。11 个职责隔离的 Skill 分工协作，用显式状态契约压住跨镜头一致性漂移，用文件系统承载唯一真相，用二值化门禁与 SHA-256 指纹锁住付费生成的成本上限。

## 一、定位与边界

工业化短剧生产里，「全自动一键出片」是个陷阱：质量不可控，算力账单也不可控。本系统的做法是把智能编排和重型渲染拆开，各自交给擅长的角色。

Agent 接管的部分是文本解构、显式状态追踪、ID 引用核查、提示词翻译、成本预览与生产调度。这些工作有确定答案，机器做得比人快，也比人稳。

音色克隆、AI 对口型与剪辑节奏卡点留给专业工具和创作者本人。这几件事没有唯一正确答案，机器代劳只会把返工成本推给后期。

## 二、业务痛点与收益

| 维度 | 对话框抽卡模式 | 本工作流 | 收益 |
| :--- | :--- | :--- | :--- |
| **一致性控制** | 靠 Prompt 隐式记忆，滑动窗口一截断就换脸 | 每镜写清起点、终点、变化与变化原因 | 跨镜头崩坏在写作阶段就被拦住 |
| **成本控制** | 盲目重试，对废图废片照样扣费 | `prepare` 先预览预算，`confirm` 锁 SHA-256 指纹，`run` 才付费 | 无效算力支出被机械拦下 |
| **质检追溯** | 只能主观说「不对劲」，定位不到哪一步 | `short-drama-review` 输出位置、证据、影响与修订要求 | 问题落到具体文件与具体镜头 |
| **交付周期** | 单集靠人肉复制粘贴，两三天 | 标准 Markdown 加插件化 adapter 批量导出 | 单集生产周期压到半天量级 |

前两行的收益来自机制本身：门禁是二值的，指纹不一致就拒绝提交，不依赖任何人的自觉。后两行来自文件契约里的引用关系，改一处能沿依赖链回溯到受影响的产物。

## 三、工作流架构

![AIGC 漫剧 / 短剧创作工作流分层架构](docs/architecture.svg)

图的可编辑源在 [docs/architecture.mmd](docs/architecture.mmd)，分层职责的逐层说明在 [docs/architecture.md](docs/architecture.md)。

两条横切能力贯穿全流程。`short-drama` 负责项目初始化、跨阶段路由、本地 Dashboard 与制作形态决策，不写任何阶段正文。`short-drama-review` 可在任意阶段介入，只输出问题、证据、影响与修订要求，不改来源文件。

生产环节是四步硬闸门，顺序不可合并：

```text
job → prepare → confirm → run
```

`prepare` 只验证并展示数量、提示词、来源、参考绑定、输出路径与 adapter，不产生费用。`confirm` 只保存与当前 job 指纹绑定的一次性确认。`run` 才启动 adapter。job、prompt、参数或输出路径任一变化，旧确认立即失效。

## 五、核心机制

### 1. 文件系统即唯一真相

每集只维护 5 份 Markdown：`剧本.md`、`视觉设定.md`、`图片提示词.md`、`分镜.md`、`视频提示词.md`。项目不另建数据库，也不另建 episode card、节拍表或 QA 记录。一份事实只有一个 owner，修改只有一条路径。

选 Markdown 而不是结构化数据库，是因为创作者要能直接读、直接改、直接否决。机械可校验的部分由字段格式约定与离线 Python 脚本补上，两者不冲突。

### 2. 显式状态契约

每个镜头必须写清四件事：

- **起点**：镜头从什么状态开始
- **终点**：镜头结束时变成什么状态
- **连续性变化**：期间发生了哪些可见变化
- **变化解释**：变化由什么动作、事实或设计锁解释

连续性不再指望模型「记得上一镜角色穿什么」，而是变成可校验的文本。上一镜没交代、世界规则不允许、也没有设计锁的变化，一律按连续性风险报出。

### 3. 四级规则与 fail-closed 门禁

离线校验脚本按四级规则拦截：

| 规则级别 | 含义 | 判定方式 | 能否阻断 |
| :--- | :--- | :--- | :--- |
| `structural_invariant` | 资产 ID 缺失、跨文档引用断裂、状态矛盾 | Python 门禁脚本 | 二值直接阻断 |
| `reviewed_invariant` | 设定与承诺未兑现 | `short-drama-review` 附证据判定 | 附证据链后阻断 |
| `craft_default` | 行业常用创作做法 | 启发式规则提示 | 创作者说明理由即可覆盖 |
| `taste_option` | 钩子类型、叙事节奏、审美品味 | 创作者主观决策 | 不自动阻断 |

`structural_invariant` 由机器判定，不需要读剧情。`taste_option` 归人，脚本不碰。

### 4. 人类停靠与 SHA-256 指纹

`confirm` 会把当期提示词、模型参数与关联资产 ID 拼接后跑一遍 SHA-256，得到一个 64 位十六进制指纹。`run` 执行前重算并比对：任何一处改动都会让指纹对不上，任务被拒绝提交。

这就是它叫 Confirm 指纹的原因：锁的不是人，是字节。

## 六、资产引用与图生视频

连贯性靠三步走：资产提示词条目定妆，分镜绑定引用，视频提示词补上运动。

1. **资产提示词条目**：`short-drama-assets` 从剧本抽出 `CHAR-001` 这类唯一资产 ID，`short-drama-image-prompts` 把它们写成 `IMG-*` 条目。`IMG-*` 只是提示词条目的 ID，不代表图片已经生成。
2. **分镜绑定引用**：`short-drama-storyboard` 在分镜里用「图片提示词项」指向已有 `IMG-*` 条目，用「输入参考图」声明这一镜真正要送进生产的参考图。后者使用完整 `REF-*` 语法，写清顺序、中文名、控制范围与不得控制范围。
3. **图生视频**：`short-drama-video-prompts` 生成运动提示词。分镜的「输入参考图」为「无」时走文生视频，可复制提示词必须自带完整的静态视觉事实；不为「无」时走图生视频，adapter 把参考图（Base64 或云端 URL）与运动提示词一起提交。

参考图的中文名、role 与允许/禁止控制范围会随确认文档一起交给 adapter。把它们降级成一串无标签文件名是不允许的。

## 八、产物样例

### 样例 1：`分镜.md` 的状态契约

```markdown
## SHOT-EP001-002 · 三步

- 来源：EP001-SC001
- 时长：11s
- 目的：用距离变化把「发现」推进成「介入」，并让观众看清男人的脸
- 景别/机位：中景，机位在沈青肩后偏右，同时容纳沈青背部与长椅上的男人
- 起点：沈青停在距长椅三步处，钥匙串在左手，视线朝向男人。
- 终点：男人转过脸，与沈青对视；沈青向前走了一步，两人距离缩短为两步。信封仍在男人膝上、两手之下。
- 连续性变化：男人由「未察觉」变为「对视」；两人距离由三步缩短为两步。信封的位置与开合状态不变。
- 变化解释：沈青开口触发男人转头，那一步把「发现」推进成「介入」。
- 声音：[SFX] 顶灯电流声持续；沈青开口时环境声压低。
- 图片提示词项：IMG-MAN-SHEET《男人造型板》（控制：发际线、颧骨旧疤、胡茬状态、服装层次）
- 输入参考图：无
```

### 样例 2：`视频提示词.md` 的运动与音频打点

```markdown
## MOTION-EP001-002 · 三步

- 分镜：SHOT-EP001-002
- 生成方式：文生视频
- 输入参考图：无
- 静态视觉锚点：中景，机位在女性肩后偏右，画面左侧前景是她的背影与侧脸……
- 起点：沈青停在距长椅三步处，钥匙串在左手，视线朝向男人。
- 主要变化：沈青开口；男人转头与她对视；沈青向前走一步，距离缩为两步。
- 终点：两人对视，距离两步，信封仍在男人膝上、两手之下。
- 运镜：轻微跟移，随沈青那一步微向前推约 10cm 后停止。
- 声音：[SFX] 顶灯电流声；环境声在沈青开口时压低。对白 [OS] 先生，末班车已经发出去了。
- 时间线打点：00:00.0 SFX-CEILING-HUM 延续；00:03.0 环境声压低，对白进入；00:09.0 环境声恢复；00:11.0 收尾。
- 对白打点：00:03.0 CHAR-SHENQING [OS]「先生，末班车已经发出去了。」；00:06.5 说完。
```

「时间线打点」与「对白打点」是给 TTS 与剪辑脚本读的元数据。秒数写清之后，配音与音效不必再靠人耳对位。

## 九、生产 Adapter 与平台解耦

job 是供应商中立的，平台差异全部落在 adapter：

- **参数映射**：adapter 把统一的 `prompt` 与 `parameters` 转译成平台私有字段。
- **网络与凭据**：adapter 自己处理鉴权、参考图上传、指数退避重试与产物下载；凭据只从环境变量读取，不写进配置、job 或运行记录。
- **参考图语义**：确认文档里的中文名称、role、可控制与不得控制范围必须原样传递，不能静默降级成无标签文件列表。

已实现的 adapter 在 `adapters/`。`base_adapter.py` 定义通用接口、SHA-256 指纹校验与任务基类，`kling_adapter.py` 是走真实 HTTP 与异步轮询的可灵实现。接线方式照抄 `config.example.json`，配置文件必须放在项目目录之外。

## 十、快速开始与校验

### 运行环境

需要 Python 3.13 或更高：校验脚本用了 `Path.is_dir(follow_symlinks=)` 这类 3.13 才引入的 API，低版本会在运行时报 `TypeError`。除此之外零第三方依赖，全部脚本只用标准库，可离线跑。

### 安装

克隆仓库，把 `skills/` 下的目录挂进支持 [Agent Skills 标准](https://agentskills.io/specification) 的宿主。pi、Codex、Claude Code 的挂载方式见 [docs/installation.md](docs/installation.md)。

### 离线校验

```bash
# 1. 跨文档结构与 ID 引用一致性
python3 skills/short-drama/scripts/creator_markdown_check.py \
  examples/minimal-drama/剧集/EP001 --project-root examples/minimal-drama
# 预期输出：OK: examples/minimal-drama/剧集/EP001

# 2. Flow 生产包结构与连续性
python3 skills/google-flow-manga/scripts/validate_flow_package.py \
  examples/minimal-drama/flow/EP001/flow-package.json
# 预期输出：OK: 0 error(s), 0 warning(s), 3 shot(s)

# 3. adapter 离线自检
python3 adapters/kling_adapter.py --selftest
# 预期输出：kling: selftest passed
```

三条都通过，说明五份文档的结构与 ID 引用自洽，adapter 的契约校验与指纹逻辑可用，可以进入生产边界。
