# Google Flow 漫剧审核规则

审核分为生成前和生成后。先定位失败通道，再决定修改哪一层。

## 生成前审核

### 1. 来源绑定

- 镜头有稳定 ID，并能追溯到具体场次/剧本节拍。
- 人物、地点、道具和引用资产 ID 都存在且已批准。
- 生产包没有用模板占位符代替真实信息。

### 2. 连续性

- `start_state` 与前镜 `end_state` 相容。
- 本镜可见变化写入 `continuity_delta` 且有原因。
- 角色身份、造型、伤势、持物、地点、时间、天气、光源和空间关系没有静默漂移。

### 3. Flow 输入适配

- 输入模式服务于镜头目标；主要角色镜头不因省事退化为纯文本抽卡。
- Ingredients 清晰、相容、用途明确。
- Frames 准确承载入口/出口状态。
- 提示词与媒体输入互补，不互相矛盾。

### 4. 镜头可执行性

- 一个短镜头只承担可完成的动作与情绪转向。
- 大动作方向先明确，再写微表情和小动作。
- 摄影运动有注意、揭示、压力、亲密或节奏目的。
- 有对白时，人物、口型、表演和声音要求不冲突。

### 5. 可剪辑性

- 景别、视线、轴线、动作方向和视觉焦点可与相邻镜头衔接。
- 关键反应、揭示或信息画面有足够停留空间。
- 不把转场、天气或特效当成无理由装饰。

## 生成后审核

分开看片，最后再综合：

- `picture`：身份、表情、动作、物件、空间、光线、天气、文字和生成污染。
- `speech`：台词、说话人、口型、停顿、重音、发音和情绪温度。
- `sound`：环境、音乐、音效、静默和对白遮蔽。
- `edit`：镜头顺序、长度、反应空间、揭示时机和节奏。
- `subtitle`：文字、时机、位置、可读性和画面遮挡。
- `flow_execution`：Ingredients/Frames 是否真的生效，是否发生身份或状态漂移。
- `audience`：观众能否迅速识别主体、理解转折并感受到预期情绪。

## 审核问题格式

每个问题写：

```json
{
  "severity": "error | warning | note",
  "code": "continuity_identity_drift",
  "shot_ids": ["EP001-S001-SH003"],
  "evidence": "角色右手持剑在片段中途变为左手，下一镜仍从右手持剑开始。",
  "viewer_effect": "动作方向断裂，观众误判为换人或跳镜。",
  "fix_layer": "continuity | reference_asset | storyboard | video_prompt | flow_package | audio | subtitle | edit",
  "required_change": "重做本镜尾段或选择右手持剑的稳定帧作为下一镜入口。"
}
```

## 批准门槛

以下任一成立即不批准：

- 身份、关键道具、伤势、地点结构或剧情阶段错误。
- 台词/字幕先于画面信息，或说话人与口型明显错配。
- 关键动作、表情或揭示只闪现，观众无法理解。
- 音乐、音效、天气、特效或摄影运动把情绪带向错误类型。
- 技术上生成成功，但首遍观看仍混乱、平、急、吵或情绪错误。

偏好不能冒充阻塞项。只有影响故事理解、连续性、生成输入或成片体验的问题才升级为生产风险。

## 修复路由

- `continuity`：状态身份、持续或变化原因错误。
- `reference_asset`：源参考本身不稳定、污染或互相冲突。
- `storyboard`：关键帧、调度、轴线或镜头职责错误。
- `video_prompt`：动作、表演、摄影或环境运动表达不足。
- `flow_package`：模式、绑定、资产名或输入组合错误。
- `audio` / `subtitle`：声音或文字层错误。
- `edit`：镜头长度、顺序、反应和揭示时机错误。

不要在错误层反复重抽。先命名失败通道和观众影响，再选择最小修复。
