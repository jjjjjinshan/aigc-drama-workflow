# Google Flow 交接规则

本文件只记录会改变生产决策的 Flow 约束。模型、地区能力和额度会变化；每次实际生成前都以 Flow 界面的当前设置为准。

## 输入模式选择

### Ingredients / References

适合：角色身份、服装、道具、场景或风格引用比精确构图更重要的镜头。

- 给每个可复用资产稳定的 `asset_id` 和 Flow 资产名。
- 角色参考尽量主体清晰、背景干净；场景和风格参考不要混入无关人物。
- 提示词必须明确每个引用在本镜中的用途，不能只上传而不说明。
- 输入媒体的视觉语言应相容；冲突的画风、时间、服装或光线属于阻塞项。

### Frames

适合：必须锁定起始构图、动作起点、视线、站位，或必须到达明确结束状态的镜头。

- 首帧是本镜 `start_state` 的视觉证明。
- 尾帧是本镜 `end_state` 的视觉证明；不是所有镜头都必须有尾帧。
- 提示词只描述两帧之间发生的动作、表演、摄影和环境变化。
- 尾帧不能偷偷加入脚本未发生的新服装、道具、伤势、人物或时间跳变。

### Text

仅用于不依赖人物/地点连续性的镜头，或创作者明确接受较低控制的探索镜头。含主要角色的连续剧镜头默认不选纯文本模式。

### Video Edit

适合：已有片段整体可用，只需修改局部元素、光线、氛围或延续动作。

- 记录输入片段和被修改的状态轴。
- 修改不能静默重置未点名的人物、道具、场景和剧情阶段状态。
- 保存需要复用的输出帧，并登记成新的引用资产或下一镜首帧。

## Flow 资产命名

建议使用可读且稳定的名字：

- `CHAR-<id>-<look>-<view>`
- `LOC-<id>-<time>-<view>`
- `PROP-<id>-<state>`
- `EPxxx-Sxxx-SHxxx-START`
- `EPxxx-Sxxx-SHxxx-END`
- `VOICE-<character-id>`

本地 `asset_id`、文件路径和 Flow 资产名必须一一对应。不要用“图1”“最终版2”作为跨镜引用名。

## 每镜提示词结构

按需包含：

1. 本镜主体与当前状态。
2. 可见动作和表演节拍。
3. 环境中的必要运动。
4. 景别、机位、镜头运动和视觉焦点。
5. 光线、天气与风格锁。
6. 对白、声音或静默要求。
7. 必须保持和必须避免的连续性约束。

不要把角色全传、整集剧情或供应商教程塞入单镜提示词。

## 生成后交接

- 将采用的输出片段登记回 `output.clip_path` 或 `output.flow_asset_name`。
- 保存可作为下一镜引用、首帧或尾帧的关键帧，并新增资产记录。
- 在 Scenebuilder 或外部剪辑中检查镜头顺序、裁切、反应时间和声音衔接；生成成功不等于序列通过。

## 当前官方能力依据

截至本 Skill 制作时，Google 官方说明 Flow 支持文本、Ingredients、Frames、视频编辑、保存视频帧和 Scenebuilder；不同模型支持的输入方式和时长并不相同，Flow 会在不兼容时提示或切换兼容模式。声音引用和自定义声音也有模式与地区限制。

- [创建视频、Ingredients、Frames 与声音引用](https://support.google.com/flow/answer/16353334?hl=en)
- [模型与功能兼容表](https://support.google.com/flow/answer/16352836?hl=en)
- [视频编辑、保存帧与 Scenebuilder](https://support.google.com/flow/answer/16935718?hl=en)
- [Flow Tools 与额度提示](https://support.google.com/flow/answer/17104535?hl=en)

这些链接用于执行时复核，不把页面内容复制成永久能力承诺。
